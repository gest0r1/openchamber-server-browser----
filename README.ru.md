# Server Browser для OpenChamber

[English documentation](README.md)

**Версия:** `0.9.0-dev.2` · **Статус:** экспериментальный; авторизация на реальных сайтах и восстановление после отказа в OpenChamber ещё не полностью проверены.

Серверный Chrome для OpenChamber. Агент управляет страницей через инструмент `openchamber_web`; пользователь видит **ту же страницу** в панели **Server Browser**, может самостоятельно авторизоваться и вернуть управление агенту. Chrome работает **на сервере OpenChamber** и не зависит от включённого компьютера Windows.

В этом форке добавлена **постоянная авторизация на уровне проекта**, в отличие от временных профилей отдельных чатов в [исходном расширении](https://github.com/JosueGalRe/openchamber-server-browser). Используются существующие механизмы browser-provider и shared-surface. Сведения об авторстве приведены в [LICENSE](LICENSE) и [NOTICE](NOTICE).

## Требования и установка

- OpenChamber **2.0.1 или новее** с поддержкой расширений Server Browser (для части действий агента нужен OpenChamber 2.5+).
- Google Chrome или Chromium **109+ на сервере OpenChamber**.
- Среда службы с поддержкой **Node.js 22+** для разработки. Git используется для определения общего репозитория и worktree.
- Разрешённый запуск службы расширения. Для headless Chrome не требуется монитор или запущенный Windows-клиент.

Откройте **Settings → Extensions → Add** и вставьте:

```text
https://github.com/gest0r1/openchamber-server-browser----.git
```

OpenChamber самостоятельно устанавливает содержимое ветки **`main`** из GitHub. Локальное клонирование и сборка не нужны: в репозитории находится готовый `service/main.js`. Если исходный Server Browser уже установлен, выберите **Replace/Reinstall** для того же ID расширения и подтвердите новые разрешения (включая запуск `git`). Затем выберите **Server Browser** в **Settings → General → OpenChamber Tools → Browser provider**.

Для установки конкретной ветки добавьте к адресу `.git` суффикс `#имя-ветки`. При установке из Git OpenChamber сохраняет выбранную ветку и проверяет обновления по версии из `package.json`. Служба браузера запускается при обращении; обычно перезапускать сервер OpenChamber или клиент Windows после установки не требуется.

## Первая авторизация и работа агента

1. Откройте нужный **проект и чат** в OpenChamber.
2. Попросите агента: «Через `openchamber_web` вызови `browser.open`, открой https://example.com и остановись. Я авторизуюсь самостоятельно».
3. Страница появится в панели **Server Browser**. Нажмите на страницу, чтобы взять управление, авторизуйтесь и выберите **Hand back to agent**. Пока управление у пользователя, действия агента блокируются.
4. Откройте **новый чат того же проекта** и перейдите на тот же сайт через `openchamber_web`. Cookies и LocalStorage должны использоваться общие.
5. Для проверки изоляции откройте другой проект: его браузерный профиль независим.

Одно только открытие панели **не запускает Chrome**. Кнопка **Open for this chat** доступна, если панель получила актуальные путь проекта и ID чата; иначе браузер стартует с первым действием агента. До появления сессии адресная строка и кнопки отключены. Встроенные инструменты `browser.*` десктопного OpenCode — другие инструменты; на веб-сервере нужно использовать `openchamber_web`.

Повторная авторизация возможна при истечении cookies, хранении токена только в SessionStorage, отзыве серверной сессии, использовании SSO/2FA. Постоянный профиль не обходит политику безопасности сайта.

## Профили проектов и жизненный цикл

- **Git-репозиторий:** идентификатор проекта вычисляется из канонического пути к **общему Git-каталогу**. Worktree одного репозитория используют **общий профиль**.
- **Каталог без Git:** идентификатор вычисляется из канонического абсолютного пути. Перемещение/переименование каталога может изменить идентификатор.
- **Разные проекты:** отдельные процессы Chrome, профили, cookies, LocalStorage и владение вкладками.
- **Разные чаты одного проекта:** общая авторизация Chrome, но **собственные вкладки**. Расширение не позволяет чату обращаться к чужой вкладке через свой API.
- **Хранение:** по умолчанию `~/.local/share/openchamber-server-browser/profiles/<sha256-project-id>/` относительно домашнего каталога серверного пользователя. Каталог профиля создаётся с правами `0700`, **не хранится в Git** и не удаляется при штатном завершении Chrome или расширения.
- **Ограничения:** не более четырёх активных чат-сессий браузера; неактивная сессия закрывается через пять минут и может вытесняться при достижении лимита. OpenChamber также вправе завершить неиспользуемую серверную службу браузера. При этом закрываются вкладки и Chrome, **не сохранённый профиль**.
- **Повторный запуск:** следующий запрос запускает Chrome с ранее сохранённым профилем. Восстановление открытых вкладок, временного JS-состояния, SessionStorage и истории **не гарантируется**.

В `0.9.0-dev.2` перед запуском удаляется устаревший `DevToolsActivePort`, проверяется отсутствие другого работающего Chrome с тем же профилем, сбрасывается состояние неуспешного старта и выполняется попытка нового запуска после неожиданного завершения. Восстановление происходит **при следующем действии**; прерванная команда агента автоматически **не повторяется**. В журнал записываются код/сигнал остановки Chrome без содержимого профиля.

## Конфигурация и безопасность локальной сети

Расширение читает необязательный файл `config.json` в каталоге установки (образец — `config.example.json`). При замене установленного расширения локальную конфигурацию может потребоваться сохранить отдельно. После изменения конфигурации перезапустите **службу расширения**.

```json
{
  "profileRoot": "/home/opencode/.local/share/openchamber-server-browser/profiles",
  "allowedOrigins": ["http://127.0.0.1:3000", "http://localhost:3000"],
  "allowedNetworks": [{ "cidr": "192.168.1.0/24", "ports": [3000, "5173-5199"] }],
  "discoverDevServers": false
}
```

`profileRoot` должен быть **абсолютным путём на сервере**; по умолчанию можно не указывать. `allowedOrigins` разрешает указанные host/port; `allowedNetworks` — ограниченные частные IPv4-сети и порты. По умолчанию доступ к внутренним и loopback-адресам **запрещён**. Не разрешайте без необходимости метаданные облака, администрирование и порты посторонних сервисов. `discoverDevServers: true` автоматически ищет подходящие активные локальные серверы разработки, но расширяет доступ; предпочтительно оставить **false**. Прокси сетевых ограничений назначается **процессу Chrome проекта**, а не временному incognito-контексту.

**Граница безопасности:** профили содержат данные авторизации. Защищайте доступ к серверу, резервным копиям и учётной записи, из-под которой работает OpenChamber. Разделение проектов действует на уровне браузерных профилей и API расширения, **но не является OS-песочницей** для вредоносного кода, запущенного от того же пользователя. Не добавляйте профили и секреты в Git. Для отзыва авторизации выйдите из учётной записи на сайте. Чтобы полностью очистить локальный профиль, остановите службу и удалите только папку нужного проекта, предварительно убедившись в её идентификаторе.

## Возможности и ограничения

Реализованы: передача управления между пользователем и агентом, вкладки и всплывающие окна, навигация, клавиатура/мышь, снимки и захваты страницы, эмуляция размеров мобильного/планшетного/настольного экрана, дополнительный режим нативных select, счётчики ошибок и предупреждений, **Browser inspector** с консолью, сетью и выполнением JavaScript на видимой странице.

Отсутствуют: встроенный Chrome DevTools, графический менеджер профилей и удаление профиля одной кнопкой, гарантированный SSO/2FA, автоматическое повторение неудачной команды агента, независимое одновременное управление несколькими зрителями. В интерфейсе одновременно выбрана одна видимая сессия. История возможностей исходного расширения находится в его репозитории; её результаты не следует считать тестами этого форка.

## Диагностика

| Симптом | Проверка / действие |
| --- | --- |
| Панель пишет «Ask the agent to open a page» | Откройте проект/чат и вызовите `openchamber_web → browser.open` либо кнопку **Open for this chat**, если доступна. |
| Агент пишет, что пользователь управляет страницей | Передайте управление обратно через панель. |
| `ECONNREFUSED 127.0.0.1:<порт>` | Определите, относится порт к **Chrome DevTools** или **службе расширения**. Разные номера портов нормальны. Проверьте процесс Chrome, статус расширения и журнал службы. В `0.9.0-dev.2` исправлен один сценарий устаревшего порта/повторного запуска, но не все причины возможного падения. |
| «Extension service stopped» | Проверьте, включено ли расширение и подтверждены ли разрешения; при необходимости перезапустите службу через Settings. Весь OpenChamber перезапускайте лишь при невозможности восстановления через настройки. |
| Сайт снова требует вход | Проверьте проект/worktree, срок жизни cookies, использование сайтом токенов только в SessionStorage. |
| Заблокирован локальный сервер разработки | Добавьте только нужный `allowedOrigins` и перезапустите службу расширения. |

При неудачном тесте **01.11.2026** служба отвечала на запрос `/health`, но процесс Chrome отсутствовал, а запрос агента обращался к устаревшему порту Chrome DevTools. **Точная причина завершения Chrome не установлена.** Исправлены выявленные слабые места механизма повторного запуска, но полноценное восстановление без участия пользователя ещё нужно подтвердить на сервере OpenChamber.

## Сборка, тесты и статус проверок

```sh
bun install --frozen-lockfile
bun run build
bun run test
bun run check
bun run package
```

`service/main.js`, `panel/main.js` и `panel/inspector.js` — готовые файлы расширения, хранящиеся в Git. После правок исходников их **обязательно пересобрать** перед публикацией. При отсутствии Chrome соответствующие тесты могут пропускаться.

**Проверка текущего форка:** выполнены синтаксические проверки JavaScript и изолированные проверки моделирования отказов. Добавлены регрессионные тесты для старого порта DevTools, повтора после ошибки запуска, общих cookies/LocalStorage между чатами, сохранения профиля, идентификации Git worktree и изоляции проектов. **Полный набор тестов репозитория и успешное восстановление реальной авторизации после отказа на рабочем сервере пока не подтверждены.** Слияние в `main` само по себе не означает готовность к эксплуатации без дополнительной проверки.
